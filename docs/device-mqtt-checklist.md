# MQTT 与统一全双工联调

2026-11-18。采用平台直接推送音频、平台管理任务结果的规则。
本文件是实板验收步骤，不代表已完成真机验证。

1. 上电待机，确认 `MQTT connected`、`SUBACK granted`，至少两次 `Status PUBACK`。
2. 待机下发提醒：确认 `Task notification queued` → `Task notifications persisted` →
   `Task notifications ready`；WebSocket 鉴权携带 task_ids，鉴权后立即连续上传麦克风。
3. 实际听完提醒后直接提问，不再唤醒。确认同一个连接可回答，提醒结束不回待机。
4. 提醒中讲话，验证平台停止后续回答；设备完整播完已缓存尾音，上行不断，
   不发送 response.cancel、不等取消确认、不因语音打断重连。
5. 正常对话/电话中下发提醒：确认当前连接收到音频，无新建连接、无重复 auth，
   不因当前正在播放而延后到挂机。平台决定优先级。
6. 对双向交替讲话、双方同时讲话分别测试。某一方持续讲话超过 60 秒不挂机；
   双方连续静默 60 秒才退出。平台连续发送静音包也不能永久维持会话。
7. 首页触屏结束会话：音频停止、WebSocket 关闭；MQTT 保持在线。
8. 重复下发同一个任务 ID：设备仍接受通知，平台负责避免重复播报；
   MQTT broker 的 PUBACK 正常，但设备不再发业务 audio_received ACK。
9. 连接过程中再下发提醒：通知保存，鉴权完成后交接，不能丢失或切断当前会话。
10. 连接最终失败：待处理通知保留，不每 5 秒重复唤醒；
    用户唤醒、网络恢复或平台新通知后可再次尝试。
11. 断网/恢复、重启、存储写失败恢复：检查 pending 通知恢复、无无限队列，
    无旧设备身份批次删除新身份通知。
12. 检查较短的提醒、长段回答和电话持续音频，即使不发任何响应结束事件也能播放，
    缓存排空后新音频可继续播放。

日志含义：

- `Task notifications handled`：本地通知已转交会话，或被用户取消；不是播报完成证明。
- `Task notifications retained`：连接未能处理通知，等待下一次明确触发。
- `Task notification save failed`：持久化失败，暂停下一次交接并重试，不清空 NVS。
- `Status PUBACK`：broker 确认状态上报，不证明音频已播出。
